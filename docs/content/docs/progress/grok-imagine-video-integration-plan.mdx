# grok-imagine-video 完整能力接入开发计划

> 状态：用户已审核通过，本地开发与静态验证已完成。本地提交仅用于固定已验收代码；完成全部分层验收前不推送、不部署、不发版。

## 一、已确认的最终口径

本次新增且只新增官方模型名：

```text
grok-imagine-video
```

不创建 `-canary`、`-test`、`-sync` 等别名，不修改或重命名现有 `grok-imagine-video-1.5`。

### 两个 Grok 视频模型必须严格分开

| 模型 | RelayBases 接入能力 | 输入 | 分辨率 |
| --- | --- | --- | --- |
| `grok-imagine-video-1.5` | 单图生视频 | 提示词 + 恰好 1 张起始图 | 480p/720p/1080p |
| `grok-imagine-video` | 文生、单图生、Reference-to-video、视频编辑、视频延长 | Text/Image/Video | 480p/720p；编辑与延长继承输入且最高 720p |

1.5 保持现状，不开放纯文生、多参考图、视频编辑或视频延长。现网实测证明：sub2 收到不兼容的 1.5 纯文字或多参考图请求时，可能把实际执行模型回落为基础版 `grok-imagine-video`。适配器必须继续阻止这种“请求 1.5、实际跑基础版”的隐式换模。

### 昨天最终确认的比例规则继续照抄

- 无限画布和视频工作台统一只展示三档：横屏 `16:9`、竖屏 `9:16`、方形 `1:1`。
- Canvas 对旧 `4:3`/`3:2` 归一为 `16:9`，对旧 `3:4`/`2:3` 归一为 `9:16`。
- 公开 API 与适配器保留 xAI 官方 7 种生成比例：`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`，避免破坏直接 API 用户。
- 视频编辑和视频延长不显示比例选择；输出继承输入视频比例。

这不是重新设计比例，而是完整复用 v0.4.14 已上线的“Canvas 三档、网关七档”规则。

### 价格规则

- 现有 1.5 基础价格保持 `0.16 元/秒`。
- 新模型严格设置为一半：`0.08 元/秒`。
- 所有模式均为异步任务，因此不乘 4。
- 不按分辨率拆价，不额外增加图片或视频输入费。

## 二、官方能力矩阵

xAI 官方模型页将 `grok-imagine-video` 定义为 `Text, Image, Video → Video`。本次五种能力全部进入开发和验收范围，不能再擅自缩成纯文生视频：

| 模式 | xAI 上游端点 | 官方字段 | 限制 |
| --- | --- | --- | --- |
| 文生视频 | `POST /v1/videos/generations` | `prompt` | 1–15 秒，7 种比例，480p/720p |
| 单图生视频 | `POST /v1/videos/generations` | `prompt + image` | 恰好 1 张起始图，1–15 秒，480p/720p |
| Reference-to-video | `POST /v1/videos/generations` | `prompt + reference_images[]` | 1–7 张参考图，最长 10 秒，480p/720p |
| 视频编辑 | `POST /v1/videos/edits` | `prompt + video` | 单个 MP4，输入最长 8.7 秒；不能指定时长、比例、分辨率 |
| 视频延长 | `POST /v1/videos/extensions` | `prompt + video + duration` | 单个 MP4，输入 2–15 秒；延长 2–10 秒；不能指定比例、分辨率 |

五种模式互斥。`image + reference_images`、编辑与延长混用、图片与视频模式混用均应在适配器调用上游前返回明确 4xx。

## 三、RelayBases 统一公开协议

### 3.1 公开端点

不修改 new-api 源码，不直接向用户暴露三套 xAI 提交端点。五种模式统一使用现有 RelayBases 异步任务协议：

```text
POST /v1/videos
GET  /v1/videos/{task_id}
GET  /v1/videos/{task_id}/content
```

当前 new-api rc.21 已有 `mode` 字段，且会把原始 JSON 的自定义字段继续转发给适配器，因此协议转换可以完全放在自研 `grok-media-adapter`，无需修改 new-api 镜像。

### 3.2 模式字段与公开请求体

Canvas 和官方 RelayBases 文档始终显式传 `mode`，不能靠素材数量猜模式。

#### 文生视频

```json
{
  "model": "grok-imagine-video",
  "mode": "text-to-video",
  "prompt": "...",
  "duration": 8,
  "aspect_ratio": "16:9",
  "resolution": "720p"
}
```

#### 单图生视频

```json
{
  "model": "grok-imagine-video",
  "mode": "image-to-video",
  "prompt": "...",
  "duration": 8,
  "aspect_ratio": "9:16",
  "resolution": "720p",
  "images": ["https://.../first-frame.jpg"]
}
```

#### Reference-to-video

```json
{
  "model": "grok-imagine-video",
  "mode": "reference-to-video",
  "prompt": "让图片1中的人物穿上图片2中的衣服",
  "duration": 8,
  "aspect_ratio": "1:1",
  "resolution": "720p",
  "images": ["https://.../person.jpg", "https://.../clothes.jpg"]
}
```

#### 视频编辑

```json
{
  "model": "grok-imagine-video",
  "mode": "edit-video",
  "prompt": "给人物添加一顶黑色礼帽",
  "video_url": "https://.../source.mp4",
  "seconds": "9"
}
```

`seconds` 是 RelayBases 的计费秒数字段，等于 `ceil(输入视频真实时长)`。适配器校验后必须在调用 xAI `/v1/videos/edits` 前剥离该字段，不能把它作为官方 `duration` 发送。

#### 视频延长

```json
{
  "model": "grok-imagine-video",
  "mode": "extend-video",
  "prompt": "镜头继续向右平移，人物走出画面",
  "video_url": "https://.../source.mp4",
  "duration": 6
}
```

这里的 `duration` 仅表示新增片段的秒数，不是输入加输出的总时长。

### 3.3 无歧义兼容规则

- `grok-imagine-video` 的正式文档和 Canvas 一律显式传 `mode`。
- 为兼容 xAI 风格的纯文本调用，可允许“没有任何媒体且缺少 mode”安全归一为 `text-to-video`。
- 只要携带图片或视频而没有 `mode`，适配器直接拒绝，不能把 1 张图擅自判断为起始图或参考图，也不能把 1 个视频擅自判断为编辑或延长。
- `grok-imagine-video-1.5` 继续沿用现有请求体和严格单图规则，不要求新增 mode。

## 四、计费设计

### 4.1 new-api 配置

```text
ModelPrice["grok-imagine-video"] = 0.08
quota = 0.08 × billing_seconds × 500000
异步倍率 = 1
```

不新增 `ModelRatio`、`CompletionRatio`、`ImageRatio`、计费表达式或 4X 字段。

### 4.2 五种模式的计费秒数

| 模式 | billing_seconds | 预期 quota |
| --- | --- | ---: |
| 文生视频 | `duration` | `40,000 × duration` |
| 单图生视频 | `duration` | `40,000 × duration` |
| Reference-to-video | `duration` | `40,000 × duration` |
| 视频编辑 | `ceil(输入视频真实时长)`，通过 `seconds` 传给 new-api | `40,000 × seconds` |
| 视频延长 | 延长部分的 `duration` | `40,000 × duration` |

示例：1 秒 40,000 quota，8 秒 320,000 quota，15 秒 600,000 quota。

### 4.3 视频编辑防少报

new-api 在没有 `seconds` 和 `duration` 时会默认按 4 秒预扣，而 xAI 编辑接口不接受 `duration`，所以不能直接照搬官方请求。

正确实现：

1. Canvas 读取源视频 metadata，发送 `seconds = ceil(duration)`。
2. 适配器必须重新物化同一份 MP4，并用 `ffprobe` 校验真实时长、容器和编码。
3. `seconds` 缺失、不是整数或与 `ceil(真实时长)` 不一致时，在调用 xAI 前返回 4xx。
4. 校验后的同一份字节通过受控 URL、临时对象或 Data URI 发往 xAI，不能校验一个可变 URL 后再让 xAI 重新读取已经被替换的内容。
5. new-api 对适配器校验失败必须完整退款；这是发布阻断测试，不能只看错误码。
6. 适配器发给 xAI `/v1/videos/edits` 时删除 RelayBases 专用的 `seconds`、比例、分辨率和 duration 字段。

视频延长有官方 `duration=2–10`，可直接作为计费秒数；输入视频时长仍需校验为 2–15 秒。

## 七、验收矩阵

### 7.1 五模式功能

| 模式 | 必须通过 |
| --- | --- |
| 文生 | 无素材；1/8/15 秒；480p/720p；Canvas 三档比例 |
| 单图生 | 1 张起始图；0 张和 2 张拒绝；图片顺序与公网 URL 正确 |
| Reference | 1/2/7 张；最长 10 秒；编号、顺序和 reference_images 映射正确 |
| 编辑 | 1 个 MP4；输入上限 8.7 秒；继承参数；seconds 与 ffprobe 一致 |
| 延长 | 1 个 MP4；输入 2–15 秒；延长 2/6/10 秒；继承比例与分辨率 |

### 7.2 比例与分辨率

- Canvas 只出现横屏、竖屏、方形，分别传 16:9、9:16、1:1。
- 公开 API 七种官方生成比例均做 1 秒真实测试；它们不重新出现在 Canvas 选择器。
- 基础版 480p/720p 成功，1080p 在上游前拒绝。
- 1.5 的 480p/720p/1080p 和单图规则继续成功。
- 编辑和延长完全不向 xAI发送 aspect_ratio 或 resolution。

### 7.3 计费与退款

- 生成类任务实扣 `40,000 × duration`。
- 编辑实扣 `40,000 × ceil(输入真实秒数)`。
- 延长实扣 `40,000 × 延长秒数`。
- 所有模式不出现异步 4X。
- 模式冲突、非法素材、非法时长、1080p、seconds 不符、适配器失败和上游失败逐项核对退款。
- 页面价格、new-api pricing、任务账单和 usage log 四方一致。

### 7.4 产品与回归

- 设置、视频工作台、画布文本/图片/视频节点均能选择并恢复正确 mode。
- 创建、轮询、完成、失败、过期、content、下载、刷新续跑和重试正常。
- 中英文真实浏览器逐页检查，无中文残留、中英夹杂或错误翻译。
- 模型广场只出现一个正式新模型卡片，无 canary、别名或重复条目。
- 1.5 不发生基础版回落；现有 Grok 图片、VEO、Nana、Seedance 和其他视频模型不受影响。
