# 待测试

- API 配置平台：默认选择亚洲站 `anyaigc.com`；切换到国际站 `anyaigc.ai` 后，媒体、文本模型读取及所有后续 AI 请求必须使用国际站域名。两个域名链接应在新标签页打开对应站点；切回亚洲站后应重新获取各站点可用模型。
- 我的素材 ZIP 导入：导入项目“导出素材”生成的备份 ZIP，确认素材信息和图片/视频文件均可恢复；导入普通 ZIP 时，确认嵌套文件夹中的 PNG、JPG/JPEG、WebP、GIF 图片均被逐张导入为独立的本地图片素材（同名文件也全部保留），非图片文件被跳过并显示数量。整个流程仅保存到当前浏览器本地存储，不上传至 AnyAIGC 平台。
- AnyAIGC Key 与模型发现：分别输入媒体和文本 API Key，确认提示选择“智能自动 / Smart Auto”分组；媒体 Key 下应提示智能自动分组可能不返回 Gemini 图片模型，使用 Nano Banana 2 / Pro 需改用已设置 Gemini 支持的分组 Key（比如：特价banana）。点击“获取模型”后，图片/视频仅显示 `/v1/models` 返回且在 Canvas 支持列表中的模型。刷新页面后，已获取的模型列表和默认模型必须保留；更换任一 Key 后，仅清空该 Key 的列表和默认模型；401/403 清空该列表，暂时网络失败保留上次成功结果。
- 图片模型：使用真实 Key 验证 `gpt-image-2`、`gpt-image-2-c`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-sunburst-c`、`gpt-image-2.5-flare`、`gpt-image-2.5-flare-c` 文生图与图生图、`gemini-3.1-flash-image-preview` 或 `gemini-3-pro-image-preview` 生图，以及 `grok-imagine-image` 和 `grok-imagine-image-pro` 文生图和单图编辑。Gemini 生图/图生图选择非 `auto` 尺寸时，请检查 `generationConfig.imageConfig`：画布尺寸会映射为 Gemini 支持的 `aspectRatio` 和最接近的 `imageSize`，例如 `768x1344` 为 `9:16` 和 `1K`。Grok 图像工作室仅允许一张参考图，编辑应提交 multipart 的 `image` 字段；蒙版编辑和多图编辑必须在提交前明确拒绝。`doubao-seedream-5-0-260128` 文生图与图生图应 POST `/v1/images/generations`，`doubao-seedream-5-0-pro-260628` 应 POST `/api/v3/images/generations`；两者均使用 JSON `image` 参考图、关闭水印、请求 `b64_json`；上游可能直接返回完整 data URL（如 `data:image/jpeg;base64,...`），界面必须按原样显示，不得再套一层 `data:image/png;base64,`。不提交 `n` / `stream` / `sequential_image_generation`。Pro 最多 10 张参考图，Lite 最多 14 张；蒙版编辑必须在提交前拒绝。
- 视频模型：使用真实 Key 验证 `grok-imagine-video` 文生视频、`grok-imagine-video-1.5` 恰好一张图片的图生视频、`kling-motion-control` 一张图片加一个动作视频、`kling-omni-video`，以及 `kling-3.0-turbo` 的文生和单图生。Omni 提交时必须映射为 `kling-v3-omni`；Kling 3.0 Turbo 文生必须使用推荐的顶层 `prompt`，并在 `settings` 提交分辨率、画面比例和时长，图生仍使用对应图生端点。两者均须按实际端点轮询，支持 720p/1080p 和 3-15 秒，并将 `task_status: "succeed"` 与 `task_result.videos[].url` 识别为完成结果。`MiniMax-Hailuo-02` 与 `MiniMax-Hailuo-2.3` 仅在 `/v1/models` 返回时显示；分别验证文生（无参考图）、图生（恰好一张首帧图）和首尾帧（恰好两张图，列表顺序为首帧、尾帧），请求应发送到 `/minimax/v1/video_generation`，仅可选 6/10 秒，并从查询响应的顶层或嵌套 `file.download_url` 完成任务。任何未在 `/v1/models` 返回的模型都不得被选择或隐式替换。
- 参考素材上传：为 Kling 提交本地图片和 MP4；图片应通过 imageproxy 上传，MP4 应按 storage.to 初始化、签名上传、确认的顺序处理。若上游不能读取 storage.to 分享链接，应展示明确错误且不得改投其他模型。
- 数据与双语：中文和英文分别覆盖首页、图片工作台、视频工作台、画布编辑器和设置。检查品牌、Logo、隐私链接、模型空状态、输入提示、错误和辅助属性；用户输入的提示词、画布名和素材正文必须保持原语言。
- Vercel：将项目导入 Vercel 并把根目录设为 `web`，部署后为 `canvas.anyaigc.com` 绑定 Vercel 指定的 DNS 记录。上线前用真实 API Key 完成一项图片和一项视频生成验证。
- Canvas Agent：分别验证在线 Agent 与本地 Agent 的 SSE / MCP / HTTP 错误、工具摘要、连接错误和诊断日志在切换语言后重算显示，用户消息、模型回复、工作区路径和上游错误不得被误译。
- Codex App 插件文档：新增插件安装教程，区分 AI 自动安装、手动安装和本仓库开发调试安装；同步优化插件 README 与技能说明。
- 配置与用户偏好：每个模型渠道新增 OpenAI / Gemini 调用格式选择，默认 OpenAI，切换默认格式时同步更新默认 Base URL；渠道 Tab 增加紧凑醒目的提醒，说明模型是否可选需要到“模型”Tab 选择。
- Gemini 调用格式：支持拉取 Gemini 模型列表，并用于文本问答、在线 Agent 工具调用、基础生图和图生图请求。
- 音频和视频生成：选择 Gemini 调用格式时先给出不支持提示，仍需使用 OpenAI 兼容渠道。
- 移动端滚动体验：全局隐藏滚动条仅在精细指针设备生效，手机触摸设备保留原生滚动行为，需验证首页、生图工作台和视频工作台的纵向滑动是否顺畅。
- Midjourney 生图：使用真实 Key 验证 `mj_imagine` 文生图与垫图（最多 5 张），以及 `mj_blend` 融图（2-5 张，仅 1 张时必须在提交前给出明确中英文提示）。MJ 为异步任务：提交返回 `code: 1` 与 `result` 任务 ID，再轮询 `/mj/task/{id}/fetch` 至 `status: "SUCCESS"`。尺寸不走 `size` 参数，而是把画面比例拼成原生 `--ar W:H` 追加到提示词，`auto` 不追加，用户已自行输入 `--ar` 时不得重复追加。出图后在结果图上验证派生操作：U1-U4 放大、V1-V4 变体、扩图 1.5x/2x、自定义缩放（1-2 倍）、局部重绘；按钮必须依据该任务返回的 `buttons` 动态呈现，已放大的图不应再出现 U1-U4。局部重绘与自定义缩放为两步流程（先 `action` 进入 modal 态，再 `modal` 提交），蒙版需转换为 MJ 约定的“白色区域为重绘区域”，请确认重绘区域与涂抹区域一致而非相反。刷新页面后对历史 MJ 图仍可继续派生操作；画布中 MJ 图节点应出现 MJ 放大/变体/扩图/重绘工具，非 MJ 图节点不应出现，派生结果落在源节点右侧的新节点并可继续链式操作。
- Midjourney 版本参数：选中 MJ 模型时生图设置应出现「MJ 版本」选项（v8 / v7 / 跟随账号），默认 v8，非 MJ 模型不应出现该选项。确认提交的 `prompt` 末尾带上对应的 `--v`；选「跟随账号」时不追加 `--v`，且会剥掉提示词里已有的版本参数。若提示词自带 `--v 7`（例如来自提示词模板），应被设置项替换为所选版本而不是出现两个 `--v`。自定义 Zoom 等派生操作也应带上相同版本。请确认上游实际接受 `--v 8`；如果该版本尚未开放，改选 v7 应能正常出图。
